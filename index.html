결제 정산 대사 자동화

2026.06 – 재직 중 · 월 단위 · 단독 수행(선임 리뷰)
Spark SQL · Databricks · Delta Lake · Python · Claude Code · MCP

IPO 준비에 따른 IFRS 회계 마트 검증. 세 개 서비스의 결제 데이터를 결제대행사(PG) 정산 자료와 거래 단위로 대조해 누락과 금액 불일치를 찾고 원인을 분류합니다. 카드, 간편결제, 가상계좌, 계좌이체, 해외 PG, 앱 인앱결제 8개 수단마다 거래ID 매칭 방식이 다릅니다.

한 일
  • PG 파일 → 임시 뷰 표준화 → 거래ID·주문 브릿지 조인 → 회계 마트 FULL OUTER JOIN → 불일치 추출. 결제수단별 쿼리를 단일 셀 단위로 표준화해 매월 재실행.
  • 결제월과 취소월이 다른 건이 순액 비교에서 금액 불일치로 잡히던 오탐을 주문/취소 상태별 분해로 해결. 다국어 상품명 필터 누락, PG별 날짜 포맷, UTC/KST 기준 차이를 건별로 규명.
  • 원인 2차 분류를 LLM 에이전트가 MCP로 Databricks를 직접 조회해 수행하도록 자동화. 근거 없는 결론은 건별 재조회로 걸러내고, 판단 불가 건에는 원시 정보 표를 붙이도록 프롬프트 재설계.
결과
금액 불일치 오탐 13건 → 6건. 해외 PG 누락 절반 이상 복구. 2026년 1~7월 전 결제수단 재대사 완료, 회계팀 소명자료 정리.
배운 것
에이전트 출력을 믿었다가 사유가 실제 데이터와 안 맞는 건을 선임 리뷰에서 지적받았습니다. 이후 모든 건을 ID로 직접 조회해 확인하는 것이 원칙이 됐습니다.

비용 수집 파이프라인 Airflow 이관

2026.07 · OpenAI · Bedrock · GCP · Anthropic · 8개 계정 · 단독
Airflow (dag_factory YAML · KubernetesPodOperator) · ArgoCD · DuckDB · Delta Lake · S3 · Secrets Manager

벤더별 Databricks Job으로 산재해 있던 AI 비용 수집을 Airflow 단일 스케줄러로 통합했습니다. OpenAI 대시보드는 저장 배치가 매일 실패하고 있었고, '사용량 × 자체 단가표' 계산이 10개월 전에 멈춰 계정별 최대 +85% 과소 · 2배 과대 오차가 있었습니다.

한 일
  • 단가표를 고치지 않고 Costs API의 실청구 금액(line_item · project 단위)을 그대로 적재하는 구조로 전환. 단가표와 계산 로직 제거.
  • api-to-json → S3 랜딩 → duckdb-to-delta → S3 external Delta 구조로 4종 통일. 벤더별 차이는 SQL 파라미터로 흡수해 이미지 재빌드 없이 YAML/SQL만으로 배포. p_date 파티션 overwrite로 재실행 멱등성 확보.
  • PR(preview 라벨) → ArgoCD 개발 Airflow 자동 기동 → 테스트 → main 머지 → 운영. 2024.09부터 백필 후 master 이관.
결과
8개 계정 전부 콘솔 청구액과 0%대 오차(최대 0.11%). 이관 중 Bedrock 6일치 금액 유실을 발견해 복구, 해당 월 비용 22.9% 정정.
배운 것
제거한 잡이 AI 서비스 필터 역할을 하고 있었다는 걸 이관 후 로우수 불일치로 알았습니다. 이관 전에 기존 잡의 코드를 먼저 읽고 역할을 목록화했어야 했습니다.

유형증상원인해결 · 결과
